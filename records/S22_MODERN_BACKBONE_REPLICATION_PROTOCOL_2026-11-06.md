# S22 现代骨干复制实验：预注册补充协议

日期：2026-11-06
状态：**草案，待用户确认骨干选型与本协议后冻结**（冻结前不得开始任何正式训练，试跑除外，见 2.3 节）

## 1. 要回答的问题

正文的四种组合（2 个数据集 × UNet、ResNet18-UNet）中，结论改变的对数依次为 25、4、2、0，效应集中在 DeepCrack537 / UNet。审稿人最可能的质疑有两条：一是这是否只是一个组合的个例，二是两种骨干都偏旧，激活都经过 ReLU。

3.4 节对效应强弱给出的解释是：下采样位置的输入经过 ReLU 后非负且大量为零，min 等依赖下尾的算子在短训练下被"饿死"，之后追赶幅度最大，各算子提升的分散由此拉大。ResNet18-UNet 的零值比例较低，min 的落后与追赶也较小。

本实验换成一种**下采样输入有正有负**的现代卷积骨干，回答两个问题：

1. 在第五种组合上，30 轮与 90 轮之间的比较结论改变多少（主端点，描述性报告）；
2. 下采样输入不再非负时，min 的短训练落后和追赶是否随之减小（机制预测，事先写定方向与阈值）。

**说明**：式 (1) 是恒等式，F_cross 完全由各算子的提升向量决定，"F_cross 随提升分散增大"不构成可检验的预测。可检验的是提升分散的**来源**，即第 2 个问题。

## 2. 骨干选型

### 2.1 候选

| 候选 | 下采样位能否换成 11 种算子 | 下采样输入的符号 | 从零训练（批量 1、无增强）的风险 | 结论 |
|---|---|---|---|---|
| SegFormer / Swin 等 Transformer | 否。下采样由带步长的 patch embedding 完成，没有池化位，硬换等于改模型 | — | 高 | 排除 |
| EfficientNet / MobileNetV2 式倒残差 | 能。块内 3×3 深度卷积的步长改为 1，其后接池化位 | 非负（ReLU6/SiLU 之后），与 UNet 同类 | 中 | 备选。机制对照弱 |
| **ConvNeXt 式（推荐）** | 能。原设计的下采样层为"归一化 + 2×2 步长卷积"，换成"归一化 + 池化位 + 1×1 卷积" | **有正有负**（残差流不经过激活） | 中。须试跑把关，见 2.3 节 | **首选** |

推荐 ConvNeXt 式：它是 2022 年以来分割中常用的卷积骨干，回应"模型偏旧"；更重要的是它的下采样输入是带符号的残差流，与 UNet、ResNet18-UNet 形成对照，正好检验 3.4 节的机制。

### 2.2 结构（记为 `convnext_unet`）

只换编码器，解码器与 ResNet18-UNet 相同，以便把差异归于编码器。

| 部分 | 设定 |
|---|---|
| stem | 3×3 卷积，步长 1，3 → 32 通道，后接归一化。不用原设计的 4×4 步长 4 patchify，保证全部下采样都发生在 4 个池化位 |
| 编码器 5 级 | 通道 32 / 64 / 128 / 256 / 512（与 UNet base 32 相同），每级 2 个 ConvNeXt 块 |
| ConvNeXt 块 | 7×7 深度卷积 → 归一化 → 1×1 卷积升到 4C → GELU → 1×1 卷积降回 C → layer scale（初值 1e-6）→ 与输入相加；相加之后**不接激活**；drop path = 0 |
| 下采样位 × 4 | 归一化 → **池化位（11 种算子之一，2×2，与另两个骨干的实现相同）** → 1×1 卷积，C → 2C |
| 解码器、分类头 | 与 `PoolAdapterResNet18UNet` 相同（转置卷积上采样 + DecoderBlock） |
| 归一化 | `--norm group`，用同一个 `_make_norm`。不用 ConvNeXt 原设计的逐像素 LayerNorm，以免归一化方式与另两个骨干不同 |
| 预训练 | 无 |

参数量在实现后由运行时实测并登记（第 8 节）。粗估：编码器约 5.6M，加解码器约 8–9M，与 UNet（7,765,985）同一量级。

### 2.3 正式训练前的三项检查（结果写入第 8 节）

1. **旧行为不变**：用改动后的脚本重跑 `b90_unet_gr_deepcrack537_max_s2026` 与 `b90_rn18_gr_deepcrack537_max_s2026` 的前 3 轮，逐轮 foreground_iou 必须与 `data/runs/` 中的记录逐位相同。
2. **结构检查**（单元测试，不训练）：模型中步长大于 1 的运算恰好只有 4 个池化位；输入 544×384 时输出为 544×384；11 种算子都能构建并前向；记录参数量。
3. **试跑把关**：`convnext_unet`、`max`、seed 2026、30 轮，跑一次，不计入正式矩阵。通过条件：无非有限梯度中止，且 MA(5) 最大值 ≥ 0.60（另两个骨干在 DeepCrack537 上 30 轮时 11 个算子的读数为 0.629–0.666）。
   - 不通过：不调学习率、不加增强、不换设定，**正式矩阵不启动**。改用备选骨干须另立协议，并在本协议第 8 节登记试跑结果。

三项都通过后，记录训练脚本与模型文件的 SHA-256，协议即冻结。

## 5. 端点

**主端点**（描述性，不设成败阈值）：F_cross(cnx) = 55 个算子对中，|Δ(a, b, 90) − Δ(a, b, 30)| > 0.005 的比例。

**机制检查与预测**：

| 编号 | 内容 | 事先写定的判据 |
|---|---|---|
| C0（操纵检查） | 训练结束时 4 个下采样位输入中恰为零的激活比例（`input_activation_zero`），用与 3.4 节相同的探针 `tools/probe_pooling_branches.py`，在验证集上统计。探针复制到 `tools_v3/s22/` 后只加 `convnext_unet` 一个分支，原文件不动 | 每个位置都 < 5%。不满足则 P1、P2 不予解读 |
| P1 | 30 轮时 `max` 与 `min` 的读数之差（3 个种子均值） | ≤ 0.015，即 3 倍最小有意义差值（按截断读数，UNet 为 0.0349，ResNet18-UNet 为 0.0065）。以固定的 `max` 为参照，避免从 11 个算子中取最好者带来的挑选偏差；阈值落在两者之间，用于区分"像 UNet 那样被零值拖累"与"没有被拖累" |
| P2 | min 从 30 轮到 90 轮的提升，在 11 个算子中的名次 | 不是第 1 名（UNet 上 min 提升最大） |

**次端点**（全部报告，不用于判定）：F_flip、M_max、各算子提升的均值与极差；三档门槛 0.0025 / 0.005 / 0.01 下的 F_cross；对 11 个算子重采样 10,000 次（seed 424242）的 95% 区间；30 轮时峰值落在末端的比例；第 4 章 g = 2 检查在本组合上的判定；`convnext_unet` 90 轮名次与另两个骨干 90 轮名次的 Kendall τ_b；每轮耗时相对 `max` 的倍数。
