## 1. 要回答的问题

正文的全部预算敏感性结果都在“5 轮预热 + 恒定学习率”下得到（2.4 节）。审稿人最可能提出的质疑是：恒定学习率下模型从不退火，各算子一直在变，结论随预算改变可能只是这种调度的产物。实践中更常见的是按总轮数衰减的调度。

本实验只改变学习率调度，回答一个问题：**在余弦衰减调度下，DeepCrack537 / UNet 上 30 轮与 90 轮的比较结论是否仍大幅改变？**

选 DeepCrack537 / UNet，是因为它是恒定学习率下效应最强的组合（F_cross = 0.455）。如果效应在这里都消失，其他组合不必再测。

## 2. 唯一的改动：学习率调度

在 `baseline_platform/tools/train_pooling_experiment.py` 中新增 `--schedule {constant, cosine}`，**默认 `constant`**，此前所有训练的数值行为逐位不变。

`cosine` 的定义（按优化器步计算，与现有 `--warmup-epochs` 的插值方式一致）：

- 记每轮步数为 S（DeepCrack537 训练集 376 张、批量 1，S = 376），总步数 T = epochs × S，预热步数 T_w = 5 × S。
- 第 t 步（从 0 计）的学习率：
  - t &lt; T_w：沿用现有 `--warmup-epochs` 的线性预热实现，不重写；
  - t ≥ T_w：lr(t) = 1e-3 × 0.5 × (1 + cos(π × (t − T_w) / (T − T_w)))，最后一步趋近于 0。
- 每次训练的余弦周期以**它自己的总轮数**为终点：30 轮训练在第 30 轮末退火到 0，90 轮训练在第 90 轮末退火到 0。两者是**相互独立的训练**，不能用截断代替。

参考实现：在现有“预热结束后返回 1.0”的分支上加一个条件即可，预热分支保持原样。

```python
import math
# 预热结束后（step >= T_w）的学习率倍数
def post_warmup_factor(step, T, T_w, schedule):
    if schedule == "constant":
        return 1.0                      # 现行行为
    return 0.5 * (1.0 + math.cos(math.pi * (step - T_w) / max(1, T - T_w)))
```

**其余全部不变**：AdamW（lr 1e-3，wd 1e-4）、有效批量 1、无数据增强、BCE + soft Dice、bf16 混合精度、GroupNorm、base 32、无预训练、数据划分 `deepcrack537_group_clean_groupv3_v7_r2_iter1`、确定性数据顺序、阈值 0.5、每轮验证一次、grad_clip 0。

### 2.1 正式训练前的两项检查（结果写入第 8 节）

1. **旧行为不变**：用改动后的脚本、`--schedule constant`，重跑 `b90_unet_gr_deepcrack537_max_s2026` 的前 3 轮，逐轮 foreground_iou 必须与 `data/runs/` 中的记录逐位相同。
2. **调度正确**：用 `--schedule cosine --epochs 30` 完整跑一次（不计入正式矩阵），读取 result.json 中每轮的 `lr_end`。预期值由同一逻辑的纯 Python 模拟算出（每轮 376 步，预热 1,880 步，总 11,280 步）：第 1、5、6、17、18、29、30 轮末分别为 2.000000e-04、1.000000e-03、9.960574e-04、5.313953e-04、4.686047e-04、3.942649e-06、0。脚本自动比对，误差不超过 1e-9 判为通过。

两项都通过后，记录脚本的 SHA-256（第 8 节），协议即冻结。

## 4. 读数

- **主读数**：与正文相同，取该次训练全部轮次中 MA(5) 的最大值（2.5 节）。
- **次读数**：最后一轮的验证 IoU。余弦调度的常见报告方式就是取终点，故一并报告。

两者都按 3 个种子取均值，得到算子在该预算下的读数。

## 5. 端点

**主端点**：F_cross(cos) = 55 个算子对中，|Δ(a, b, cos90) − Δ(a, b, cos30)| > 0.005 的比例（主读数）。

**次端点**（全部报告，不用于判定）：

1. F_flip、M_max、各算子提升的均值与极差（式 (1) 在任何调度下都恒成立）；
2. 逐种子 F_cross；三档门槛 0.0025 / 0.005 / 0.01 下的 F_cross；
3. 对 11 个算子重采样 10,000 次（seed 424242）的 95% 区间；
4. 次读数（终点值）下的 F_cross；
5. 跨调度一致性：cos90 与恒定学习率 90 轮之间，配对差差值超过 0.005 的比例，以及两者名次的 Kendall τ_b；
6. cos30、cos90 各自的峰值贴边比例（MA(5) 最大值落在最后两轮内）。

## 6. 预先写定的解读

以下判定在看到任何结果之前写定，结果出来后不再调整：

| 主端点 | 判定 | 论文怎么改 |
|---|---|---|
| F_cross(cos) ≥ 0.25（≥ 14/55） | 敏感性在余弦调度下仍然存在 | 主张推广到恒定学习率与余弦调度两种做法；6.5 节的局限改为已检验 |
| F_cross(cos) ≤ 0.10（≤ 5/55） | 敏感性在余弦调度下大体消失 | 主张收窄为“恒定学习率或早停的做法”；把“按预算缩放调度”作为缓解手段写进报数清单；摘要与结论相应修改 |
| 0.10 &lt; F_cross(cos) &lt; 0.25 | 减弱但未消失 | 如实报告两种调度的数值，主张写为“余弦调度下减弱但仍存在” |

无论结果如何，本实验都完整写进论文（新增一节或并入第 4 章），不因结果不利而省略。
