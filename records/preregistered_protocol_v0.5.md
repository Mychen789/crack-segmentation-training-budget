## 1. 算子对比的统计口径，本版最重要的一条

### 1.1 实测

2026-09-23 的决策日志 §4.5 曾据"相邻算子间距 0.0009 只有臂内噪声 0.0042 的
0.20 倍"写下"给算子排名不是测量"。2026-09-29 按种子配对重算，推翻该表述：

| 量 | 数值 |
|---|---|
| `btsp` 减 `fixed_max_avg` 的六个配对差 | −0.0075、−0.0039、−0.0058、−0.0023、−0.0052、−0.0044 |
| 配对差均值 | −0.0049 |
| **配对差的 sd** | **0.0018** |
| 两臂各自的边际 sd | 0.0296 与 0.0287 |
| **比值** | **约 16 倍** |
| 55 个算子对中区间离零者 | **29 对** |
| 去掉 `min` 后 45 对中区间离零者 | 19 对 |

**标准差的约定在此写死：全部用样本标准差（除以 n−1）。**
此前记录中的 0.0016 与 0.027 是总体标准差（除以 n），两种约定下比值都约 16，
但混用会让读者无法复核，所以统一到样本约定。2026-10-10 实算确认上表。

### 1.2 条款

1. **任何算子间比较一律报配对统计量**：同种子配对、配对差的区间、逐种子符号一致性。
2. **禁止用边际 sd 论证"差异测不出"。** 边际 sd 支配的是单臂均值的不确定度，
   不支配配对对比。此前的那条论证即为误用，已撤回。
3. 边际 sd 仍须报告，但只用于描述单臂水位的不确定度。
4. **逐种子符号一致性与区间并列报告**，不得只报其中一个。
   `min` 换骨干 3/3 同号与 `btsp` 2/3 同号的差别，正是这条要保住的信息。

### 1.3 这条有文献依据，而且是本项目踩中了已有的警告

arXiv 2103.03098（Accounting for Variance in Machine Learning Benchmarks）
明确写有"对每一对算法复用同一种子，能在不增加样本量的前提下可靠检出更小的差异"。
arXiv 2512.24145 给出适用条件：结果须在种子层面正相关，无相关性时该收益消失。
arXiv 2609.24144 给出反例：LLM 强化学习中配对降低奖励对比方差但提高梯度方差。

**所以 §1.1 那个错不是本领域缺少规范，而是本项目没有遵守已有的规范。**
这一点必须写进论文而不是藏起来：它把主线 B 的主题从
"预注册防不住不可检验的条件"推进到"**连文献里已有警告的陷阱也防不住**"。
详见 S13 §2。

## 2. H2 的处置与分层的地位

### 2.1 实测

| 量 | 数值 |
|---|---|
| DeepCrack537 低 CNR 层的 group 数 | **2** |
| 该层的图像数 | **4**（组大小 1 与 3） |
| 总体的跨度／臂内 sd 比 | 5.19 |
| 各分层的同一比值 | **0.75 至 4.40** |
| 高 CNR 层 | 跨度低于臂内噪声 |

### 2.2 条款

1. **H2 的分层主要条件在当前冻结划分上记为 NOT EVALUABLE，不记为"未通过"。**
   两组四图不支持任何区间判定，这是算术事实而非证据不足。
2. **不得为此调整分层阈值。** 阈值由 train 侧预先生成并冻结，
   事后按结果调阈值即为本项目所批评的做法。
3. **不得把分层当作提高灵敏度的手段。** 实测分层后噪声涨得比差异快，
   高 CNR 层的跨度甚至低于臂内噪声。分层的用途只剩一条：
   **检验某个机制主张是否在它声称的那一层成立**，而不是找出显著性。
4. 若要恢复 H2 的可评估性，只有两条合法途径，且都须另行签发协议版本：
   扩充该层的 group 数到可判定规模；或预先登记一个不同的划分用于未来阶段。
   **两条都不得回溯适用于已落盘的结果。**

### 2.3 一条必须一并报告的反向结果

BTSP 在它设计立论所针对的低 CNR 层比匹配对照**更差**（宏平均 −0.0043，
CRACK500 单侧 −0.0049，7 组 124 图），而在细宽度层反向 +0.0068。
**两个分层指向相反。** 这条不因 §2.2 的 NOT EVALUABLE 而免于报告：
不可评估的是 H2 的区间判定，不是这组描述性数字。

## 3. clDice 与 Boundary-F1 的现状

### 3.1 clDice：拓扑禁用解除一半

v0.4 §3.3 的禁令是"在替换为保连通性的细化算法之前，clDice 只能描述为
带容差的区域相似度，不得以拓扑或连通性名义引用"。

2026-09-29 已把骨架换为 Zhang-Suen 细化，**连通分量数在全部测试图像上与掩膜相等**。
换骨架后 CRACK500 由 0.8251 升到 0.8362、DeepCrack537 由 0.8468 升到 0.8773。

**因此：**

- **"不得以拓扑或连通性名义引用"这一条解除。**
- **"不得用于跨数据集比较"这一条不解除。** 骨架密度仍随笔宽变化，
  两数据集笔宽中位数 19.8 对 4.7 像素，该来源未被骨架替换触及。

### 3.2 Boundary-F1 不变

v0.4 §3.1 与 §3.2 原样有效：0.01×对角线、原生网格、Chebyshev 邻域、
对称膨胀求交故 precision 与 recall 是上界；跨数据集比较仍然无效。
修正后两数据集落差由 2.43 倍收到 1.14 倍，但对角线比例随图像尺寸而非笔宽缩放，
这一条没有变。

### 3.3 一条执行纪律

采用 `BCE + Dice + w · soft-clDice` 的 run，其 clDice 读数**不是独立证据**
（v0.4 §4.2 已定）。本版补一句：**该标注必须落在报表的行上，不能只写在脚注里。**

## 5. 对照规格：§9 的增订

v0.4 §9 的三项匹配要求（有效自由度、初始函数、参数计数，以前两项为准）**全部保留**。
本版增订一条排序，且这条来自文献而非本项目：

### 5.1 新增 §9.5：匹配的首选方式是缩小被检方法

存在两种达成"参数匹配"的做法：

| 方式 | 做法 | 能否产生死参数 |
|---|---|---|
| **S 缩小法** | 缩小**被检方法**以匹配对照 | **不可能**，对照未被改动 |
| **P 加法** | 给**对照**加参数以匹配被检方法 | **可能**，这正是 §9.3 四个实例的共同形态 |

**条款：优先采用缩小法。** 只有在缩小被检方法会破坏其机制时才允许加法，
且须写明为什么不能缩小。

文献中两种做法都有实例：arXiv 2505.06708 减 FFN 宽度，
arXiv 2510.08368 下调隐层大小并给出可解公式。
**本项目 §9.3 的四个实例全部属于加法，没有一个用了缩小法。**

### 5.2 §9.3 的四个实例，表述收紧

四个实例本身不变，但**不得由它们推出领域性主张**，见 §9。

## 6. H1 失败机制的精确表述

### 6.1 v0.4 的表述偏粗

v0.4 §1.1 写的是"窗口 bottom-2 均值精确为零的比例在各下采样层为 52% 至 91%，
在这些位置 V1 退化为带增益的上尾单支"。这句把因果放在零值率上。

### 6.2 实测给出的是一条更窄也更硬的机制

2026-10-10 补全 11 算子 × 3 种子的第二骨干矩阵后，按种子配对的变化：

| 算子 | 换骨干后的变化 | 逐种子同号 | 对下尾的依赖 |
|---|---|---|---|
| `min` | **+0.0253** | **3/3** | 完全依赖 |
| `diag_partition_matched` | +0.0088 | 3/3 | 按位置划分，不读秩 |
| `v0_max_mean_min` | +0.0047 | 2/3 | 三统计量含 min |
| `btsp` | **+0.0017** | 2/3 | **可加权到上尾** |

受益幅度按"对下尾的依赖程度"单调排序，`min` 是 `btsp` 的 **14 倍**。

### 6.3 条款

**H1 失败机制的登记表述改为：**

> 零值率确实起作用，但只约束**无法回避下尾**的算子，不约束 BTSP。
> BTSP 的可学习融合标量**学会了不用下尾**（浅层 alpha 达 0.70 以上），
> 所以降低零值率对它没有帮助。

> **限定，2026-10-12（S14 §2）。** 上面这段的**前半句只对 DeepCrack537 成立**。
> CRACK500 的 33 支第二骨干跑完后，依赖度与增益的 Spearman 由 +0.907 掉到 +0.391，
> `min` 减 `btsp` 的配对差 1/3 同号，11 个算子的增益全部同向、跨度仅 0.0040。
> **因此"零值率只约束无法回避下尾的算子"不得作为一般性机制陈述**，
> 须写成"在 DeepCrack537 上观察到，CRACK500 上不复现"。
>
> **后半句不受影响。** "BTSP 的融合标量学会了不用下尾"由两项直接测量支撑：
> H1 条件 5 的下尾删除测试（宏平均 −0.0036）与浅层 alpha ≥ 0.70。
> 两者都不经由 M7。**失去的是解释，不是现象。**

这条与 H1 条件 5 的下尾删除测试结果同向：删掉下尾后宏平均只动 −0.0036，
因为那条分支本来就没在用。**两条证据指向同一件事：问题不在下尾读到零，
而在那个融合标量会主动绕开下尾，于是 BTSP 收敛到一个上尾单支的邻域。**

### 6.4 2026-09-29 的一句过强表述已撤回

S12 §6 曾写"零值率是伴随现象不是原因"。该句**过强**，已在 S12 §11 更正。
正确表述见 §6.3。

### 6.4 P5 与 P6 的判定（2026-10-25，S15）

90 轮矩阵判定：**P6 成立**（`min` 减 `btsp` 失去 3/3 同号，降到 2/3），
**P5 不成立**（Spearman +0.646，判据为 < 0.600，差 0.046 未达，**未改判**）。

按 S14 §5.3 的预先合并规则，落在**"部分"**档：**§6.3 的机制部分是偏短预算的产物。**
`min` 的换骨干增益由 +0.0253 缩到 +0.0102，依赖度与增益的相关由 +0.907 掉到 +0.646，
增益跨度减半。**因此 §6.3 的限定再加一层：该机制既限于 DeepCrack537，
又部分由 30 轮的偏短预算造成。**

后半句（融合标量学会不用下尾）仍不受影响，它由两项直接测量支撑。

### 6.5 新增条款：零值率必须指明是哪一个零值率

2026-10-10 查出 S9 §1 的表把两个量填在一张表里：其余各行是
**`input=0`**（进入下采样点的激活恒为零的比例），"已训练"那一行是
**`lower=0`**（2×2 窗口 bottom-2 均值恒为零的比例）。后者比前者高 2 到 8 个百分点，
因为四个值里有两个为零就够了。

**条款：凡报告零值率，必须写明是 `input=0` 还是 `lower=0`，并且同一张表内不得混用。**
两者在本项目中都有用（前者刻画激活稀疏，后者刻画下尾分支是否带信息），
但它们不是同一个量，混用会把训练效应算大约 2 个百分点。

同口径的正确数值：UNet `norm=group` 的 `input=0` 由未训练 49.8% 升到训练后 88.6%。
机制结论（§6.3）不受影响。

**附带条款：复现说明必须含种子值。** 同一份 S9 的复现说明漏了种子（是 0，不是矩阵用的
2026），也漏了"池化算子会影响下游采样点的读数"，于是按它复现不出它自己的表。
**凡结果文件给出复现说明，须含种子值、所用算子、以及 train/eval 模式。**

## 7. 第二骨干的地位

### 7.1 实测

三个维度的排名稳定性，Kendall tau-b：

| 扰动的维度 | tau-b |
|---|---|
| 换数据集 | 0.500 |
| 换报数口径 | 0.600 |
| **换骨干架构** | **0.673** |

更强的一层：主骨干 29 个可分辨配对中 11 对在第二骨干仍可分辨（转移率 38%），
**方向反转 0 对**。

### 7.2 条款

1. **第二骨干由"稳健性附录"升为主表的一列。** 理由是实测：
   架构是三个扰动维度中**最不敏感**的一维，所以它提供的是可比较的第二读数，
   不是一个弱化的旁证。
2. **跨数据集结论须按最脆弱的一维加注。** tau-b 0.500 意味着换数据集近乎
   抛硬币，任何跨数据集的排名陈述必须同时报配对转移率。
3. **"转移率 38%、反转 0 对"这组数字优先于 tau-b 数值报告。**
   它区分"结论消失"与"结论翻转"，而 tau-b 把两者混在一起。

### 7.3 这一条在文献中是空缺，因此表述须保守

检索未找到任何工作直接测量架构族排名在换数据集时的变化
（相关的是 Hardt 2025 与 MMLU 学科间排名变动，但对象是模型而非架构族）。
**空缺不等于新发现。** 本项目这组数字的规模是 11 算子、1 数据集、2 架构，
不足以支撑任何一般性断言，论文中须与规模一并陈述。详见 S13 §3。

## 9. C6 的领域性主张：不得声称

### 9.1 实测

按 S5b 在采样前写定的判据执行系统抽样，首轮纳入 4 篇、5 条陈述：

| 标签 | 条数 | 比例 |
|---|---|---|
| A 可检验 | 5 | **100%** |
| C 不可检验 | 0 | **0%** |

C 类比例 0% 落在 S5b §5 预先规定的"< 20%"档，该档的预先解读是
"**不支持**：多数论文给出了足以检验的信息，C6 应降级为本项目内的四个实例"。

### 9.2 条款

1. **C6 不得声称领域性。** 它的依据回落到项目内四个实例。
2. **S5 §4 的"G3 部分关闭"撤回。** 已执行。
3. **C6 的表述改为** §5.1 的形式：存在正确做法与可能出错的做法，
   文献中两者都有，而报告惯例通常不让读者分辨论文用的是哪一种。
4. **n=4 不足以支撑任何关于文献分布的断言，包括"不支持"这一断言本身。**
   正确表述是"首轮证据的方向不利于 C6 的领域性主张，且未发现一个 C 类实例"。

### 9.3 不继续扩大样本的理由，三条全部是方法学理由

- 单一编码者，首轮已出现两条分歧读法，扩大样本只会线性放大未受控的编码者效应；
- 判据在前三篇里触边界两次，应先让第二位编码者复核已有 5 条，而不是先把 n 做大；
- **已知首轮零 C 类，此时带着"需要找到 C 类"的预期继续检索会污染查询词与纳入判断。**
  这正是主线 B 所批评的做法。

第二轮须另写协议、在采样前写定，判据改为 S5c §4.2 提出的
"论文自己的公式与论文自己报告的参数量是否对得上"，**不得用首轮数据回测**。
